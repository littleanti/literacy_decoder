## 🚧 Phase 0 — 데이터 모델 + 호환 검증

**목표**: 본 게임이 5단계 / 7단계와 단절 없이 작동하도록 데이터 출발점 스키마 확정.

- [ ] **한자 마스터 DB 스키마 확정** (`data/hanja.js`)
  - 8급 ~ 준4급 약 500자, sound / meaning / strokes / grade 필드
  - 5단계의 향후 DB가 본 스키마를 그대로 채택할 수 있는지 검증
- [ ] **지문 코퍼스 메타 스키마 확정** (`data/corpus/manifest.json`)
  - 학년 / 난이도 / 글자수 / 빈칸 위치 / 보스 연결
- [ ] **사자성어 import 호환** (`data/idioms.js`)
  - 7단계 `SAJASUNGO_DATA` 직접 import 동작 확인
  - 형태소 분해 메타(`hanja: ["東","問","西","答"]`) 추가
- [ ] **IndexedDB 스키마 정의** (`storage.js`)
  - 5단계와 호환 가능한 progress / hanjaMastery / bossPassed 테이블
- [ ] **빌드 마커 명세** (`{{단어:漢字}}` 토큰 → JSON 변환)
  - `scripts/build-corpus.js` (Node) 또는 수동 작성

**산출물**: `data/` 디렉터리 + 스키마 문서 1편 (TRD §3 보강)

## 🚧 Phase 1 — 입문 난이도 MVP

**목표**: 100자 내외 지문 1편 + 빈칸 1개 + 형태소 도크의 핵심 루프를 끝까지 작동.

### Phase 1.1 — 시작 화면 + 라우팅
- [ ] `index.html` 골격 + 화면 슬롯
- [ ] `main.js` 진입점 + `ui.js` 화면 전환
- [ ] 학년 선택 (5 / 6) + "이어하기" / "처음부터"
- [ ] localStorage 사용자 ID 생성 (UUID v4) + grade 저장

### Phase 1.2 — 지문 렌더
- [ ] `corpus.js` lazy-load (manifest → 본문)
- [ ] `reading.js` 지문 텍스트 렌더 + 빈칸 셀 마킹
- [ ] 빈칸 셀 활성화 인터랙션 (탭 / 클릭)

### Phase 1.3 — 형태소 도크
- [ ] `morpheme.js` 도크 렌더링 (하단 sticky)
- [ ] 디스트랙터 알고리즘 (Phase 0의 한자 DB 활용)
- [ ] 형태소 카드 음·뜻 표시 (입문 난이도)
- [ ] 카드 → 빈칸 드래그 매칭 (자성 스냅 ±20dp)

### Phase 1.4 — 채점 (어원 풀이는 Phase 4에서 강화)
- [ ] 정답 시 단어 채워짐 + 단순 ✓ 토스트
- [ ] 오답 시 카드 원위치 + 형태소별 ✕ 표시
- [ ] 모든 빈칸 완료 → 종료 화면 (점수만)

### Phase 1.5 — 영속화 기본
- [ ] IndexedDB 진척도 저장 (corpusId, accuracy, completedAt)
- [ ] 새로고침 후 "이어하기" 동작

**산출물**: 입문 지문 5편 + 핵심 루프 동작 데모. 모바일 세로 작동.

## 🚧 Phase 2 — 중급 난이도 + 페이지네이션

**목표**: 300 ~ 500자 지문을 폰 화면에 분할하고 빈칸 2 ~ 3개를 자연스럽게 처리.

- [ ] **모바일 페이지네이션** (`paginateForMobile`)
  - 빈칸 단위 분할, 빈칸이 항상 상단 50%에 위치
  - 페이지 인디케이터 (1/4, 2/4 ...)
  - 좌우 스와이프 + 키보드 좌우 화살표
- [ ] **태블릿 분할 레이아웃**
  - 좌 65% 지문 / 우 35% 도크 + 어원
  - `@media (min-width: 768px)` 분기
- [ ] **빈칸 ↔ 형태소 카드 드래그** (태블릿 정밀 작업)
- [ ] **중급 난이도 디스트랙터 강화** — 음만 표시 (뜻 숨김)
- [ ] **지문 코퍼스 30편 추가** (중급 난이도)
- [ ] **읽기 속도 측정** — 페이지 전환 timestamp 기록 → session.charsRead / elapsed

**산출물**: 중급 지문 30편 + 폰/태블릿 분기 작동.

## 🚧 Phase 3 — 심화 난이도 + 사자성어 보스

**목표**: 800자+ 지문 처리 + 사자성어 보스 스테이지로 7단계 게이트웨이 완성.

### Phase 3.1 — 심화 지문
- [ ] 800자+ 지문 페이지네이션 (4 ~ 6 페이지)
- [ ] 빈칸 4 ~ 5개, 형태소만 표시 (음·뜻 모두 숨김)
- [ ] 한자 long-press 툴팁 (학습자가 모르는 한자 확인용)

### Phase 3.2 — 사자성어 보스
- [ ] `boss.js` 진입점
- [ ] 4×1 형태소 슬롯 격자 + 후보 형태소 4 ~ 6개
- [ ] 짧은 일화 지문 + 4개 형태소 힌트
- [ ] 정답 인정 (4글자 순서 일치)
- [ ] 보스 통과 → `bossPassed[idiomId] = true` flush
- [ ] 7단계 게이트웨이: `bossesPassed` Set 노출 (7단계가 읽을 수 있도록)

### Phase 3.3 — 7단계 데이터 통합
- [ ] `idioms.js`가 `../../7_four-character_idiom_crossword/data.js`의 `SAJASUNGO_DATA`를 직접 import
- [ ] 보스용 메타 (`hanja`, `contextStory`) 별도 매핑 파일 — 코어 데이터는 7단계가 진실의 근원

**산출물**: 심화 지문 20편 + 보스 스테이지 10편 (사자성어 10개) + 7단계 통합 검증.

## 🚧 Phase 4 — 어원 풀이 + TTS + 루비 텍스트

**목표**: 학습자가 정답 후 "왜 그 단어인가"를 이해하고 한자를 자연스럽게 흡수.

- [ ] **어원 풀이 팝업** (`reading.js`)
  - 정답 직후 모달: `農夫 = 농(農: 농사) + 부(夫: 사내) → 농사 짓는 사람`
  - 형태소별 카드 + 애니메이션 (개별 등장)
  - 닫기 또는 자동 닫힘 (3초)
- [ ] **루비 텍스트** — 정답 공개 후 한자에 음·뜻 ruby
- [ ] **한자 long-press 툴팁** — 모바일에서 한자 확인
- [ ] **TTS 지문 낭독** (`tts.js`)
  - 🔊 버튼 (지문 상단)
  - 페이지 단위 낭독 + 빈칸은 침묵 / "음음" 처리
- [ ] **TTS 한자 음 발음** — 어원 팝업의 한자 클릭 시 음 재생
- [ ] **자동재생 정책** — 사용자 첫 인터랙션 후만
- [ ] **TTS 미지원 브라우저** — 🔊 버튼 비활성 + 힌트

**산출물**: 학습 효과를 결정짓는 핵심 UX 완성.

## 🚧 Phase 5 — 학습 기록 + SRL

**목표**: 누적 학습이 한 곳에 시각화되고, 망각 곡선에 따라 복습이 트리거됨.

- [ ] **대시보드 화면** (`dashboard.js`)
  - 누적 어휘 / 한자 / 사자성어 카운터
  - 일별 정답률 곡선 (Vanilla SVG)
  - 자주 틀린 한자 Top 10
- [ ] **읽기 속도 그래프** — 주차별 자/분
- [ ] **SRL 스케줄러** (`srl.js`)
  - 망각 곡선 (1일/3일/7일/14일/30일) 큐
  - 다음 세션 시작 시 복습 한자 우선 등장
- [ ] **복습 알림** — 사용자가 명시적으로 알림 권한 부여 시
- [ ] **학부모 PIN 잠금** — 대시보드 진입 시 PIN 입력
- [ ] **데이터 export / import** — IndexedDB → JSON 다운로드 (백업)

**산출물**: 학부모도 활용 가능한 진척도 대시보드.
